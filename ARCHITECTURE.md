# ARCHITECTURE — MOBA Mechanics Trainer (working title)

Target: Unity 6000.5.4f1 · URP (Universal renderer) · Input System only · UGUI + TMP · Windows x64 (Steam-ready).
The visual and audio identity follows `DESIGN_NOTES.md`.

File name = class name. Namespace `MobaTrainer.<Area>`. The reference style is kept: Manager/Mode/UI suffixes, `[Header]`/`[Tooltip]` fields, and `Instance` for global services.

## 2. Scenes & flow  *(updated at M1)*
- **Single scene `Main.unity`**, like Blindfold Chess. `GameFlowController` swaps panels and enables the `Arena` root only while a run is active. Everything is generated by **Tools > MOBA Trainer > Build Main Scene**.
- `Systems` (SettingsManager, InputManager, CursorService, UIAudio, MusicManager), `Main Camera` (MobaCameraController), `Arena` (floor, FX, player skills, cast indicator, Player, Sandbox), `UI` canvas (MainMenu, HUD, Pause, Settings), `CursorCanvas` (virtual cursor).
- Panel changes use `UIPanel` (0.15 s CanvasGroup fade, unscaled time), hover clack and click SFX.
- asmdefs are deferred until the codebase is bigger. For now it compiles into Assembly-CSharp, with namespaces already per area.

## 3. Core systems

| System | Responsibility | Key points |
|---|---|---|
| **InputManager** | Wraps `MobaControls.inputactions`; exposes gameplay actions as events or polled state | All bindings rebindable (`PerformInteractiveRebinding`); overrides saved as JSON; action maps: Gameplay, UI, Global (F5 restart, Esc pause) |
| **CastModeSettings** | Per-key cast mode: Normal / Quick / Quick+Indicator | Consumed by `AbilityCaster`; Normal = press → indicator → click to confirm (right-click cancels) |
| **CursorService** | Custom software cursor, sensitivity multiplier, confine to window | The sensitivity setting scales cursor movement through `Mouse.WarpCursorPosition` delta handling. Optional; off by default because it overrides the OS cursor |
| **MobaCamera** | Angled top-down (≈56° pitch, perspective, low FOV) | Lock toggle (Y), edge-pan when unlocked, hold Space to center, clamp to arena bounds |
| **PlayerController** | Right-click move (hold to repeat), move-indicator VFX, stop (S), hold (H), attack-move (A + click) | Movement is kinematic on the XZ plane with no NavMesh. The arena is open, which keeps it deterministic and GC-free. Obstacles use simple circle/box collision |
| **AttackController** | Attack range, windup, attack speed (cooldown), projectile or instant | Precise orb-walk: a move order during windup cancels the attack. After windup the hit is committed and the move is free. Exposes the metrics DPS uptime, cancelled attacks and APM |
| **AbilitySystem** | Q/W/E/R + D (Blink) + F (Heal/Shield) from `AbilityDefinition` SOs | Skillshot line, circle, blink, shield; cooldown UI on the HUD |
| **ProjectileSystem** | All enemy and player projectiles/telegraphs | `Pool<T>` pre-warmed per type. Plain C# data arrays are updated in one `Update` (no per-object MonoBehaviour Update). Types: Linear, CircleDelayed, Cone, GroundZone, Homing, Wall. Hit tests are analytic (circle-vs-capsule), not physics |
| **UnitSystem** | Creeps/targets/chasers with HP bars | Pooled; last-hit gold "pop"; behaviors: Strafe, Juke, Chase, Wave-march |
| **ScenarioBase** | Abstract lifecycle for each mode | `Setup(ScenarioConfig)` → `Countdown` → `Tick(dt)` → `Pause/Resume` → `End(RunResult)`; instant restart; custom slider schema via `ScenarioParam` list |
| **ScenarioRunner** | Owns the active scenario, countdown, pause, restart, playlist chaining | Publishes `RunStarted` / `RunEnded` events |
| **ScoreSystem / RunStats** | Collects metrics during a run | Pre-allocated counters, reaction-time ring buffer, APM counter |
| **RankSystem** | Tier thresholds per scenario + difficulty | Original tier names (proposed): **Ash → Ember → Iron → Obsidian → Wraith → Eclipse → Sovereign** |
| **PlaylistSystem** | Chains scenarios with configs | Defaults: "5-Minute Warmup", "Mechanics Check", "Last-Hit Drill" |
| **SaveSystem** | JSON in `persistentDataPath/` | `settings.json`, `bindings.json`, `history/<scenario>.json`, `playlists.json`; atomic write (tmp + rename); versioned DTOs |
| **SettingsManager** | Port of the reference manager, extended | SFX / music / master volume, FPS cap (60/144/240/unlimited), vSync, resolution / window mode, cursor, cast modes |
| **IPlatformService** | Achievements, cloud-save hooks, stats | `LocalPlatformService` now. `SteamPlatformService` later behind `#if STEAMWORKS` |

## 4. Performance rules (144+ FPS, no GC during a run)
- No `Instantiate`/`Destroy`, LINQ, closures, string concatenation or `foreach` over interfaces in hot paths.
- HUD numbers update only when they change, using cached `TMP_Text.SetText(format, value)`.
- Every projectile, unit and indicator is pre-warmed in pools at scenario Setup.
- Telegraphs use one shared material with a MaterialPropertyBlock (fill progress, color) so they batch with SRP Batcher/GPU instancing.
- A Profiler marker on each system. The debug overlay (F3) shows FPS, frame time, GC alloc per frame and active pooled objects.

## 5. Data model (ScriptableObjects)
- `ScenarioDefinition`: id, display name, typed code (for example `d1`), description, scenario prefab, param schema, presets, rank table.
- `DifficultyPreset`: Easy/Normal/Hard/Insane value sets for that scenario's params.
- `AbilityDefinition`: shape, range, speed, width/radius, cooldown, cast time.
- `RankTable`: ordered score thresholds per difficulty.
- `PlaylistDefinition`: an ordered list of (scenario, preset/custom config, duration).
